PART 1: WHAT IS SOFTWARE?

Software is a set of instructions that tells a computer what to do. Every app on your phone — WhatsApp, Instagram, Google Maps — is software.

Code is the text that programmers write to create software. Fairshift uses:

  • JavaScript — For websites and servers
  • Dart — For mobile apps (via Flutter)
  • Python — For voice processing
  • SQL — For talking to databases
  • HTML/CSS — For how web pages look

Frontend vs Backend

Every web application has two halves:

Frontend = What you see. Buttons, text, animations on your screen. Runs in your browser. Backend = What you don't see. The server that processes data, runs AI, stores information.

Analogy: A restaurant. The frontend is the dining room. The backend is the kitchen. The API is the waiter carrying orders between them.

What is an API?

An API (Application Programming Interface) is a messenger between software systems. When the Fairshift dashboard needs your leads, it asks the API. The API fetches from the database and returns the data. Every button click, every page load goes through the API.

What is a Database?

A database is organized storage. When you save a lead's name and email, it needs to live somewhere permanent. Fairshift uses PostgreSQL (via Supabase) — the most advanced open-source database.

What is JSON?

JSON is how data is formatted when sent between systems:

{ "name": "John", "email": "john@acme.com", "score": 85 }

Think of it as a structured form — each field has a name and a value.

What is a Webhook?

A webhook is a notification from one system to another. Analogy: Instead of calling the pizza shop every 5 minutes asking "Is it ready?", the shop calls YOU when it's done. That's a webhook.

What is a Cron Job?

A scheduled task that runs automatically. Analogy: An alarm clock for software. "Every 6 hours, check if any leads are stale." Fairshift runs 8 automated watchers this way.

AI is software that can make decisions and generate responses it wasn't specifically programmed for. Traditional software: "if X, do Y." AI software: understands context and generates appropriate responses.

What is an LLM?

A Large Language Model understands and generates human language. It's been trained on billions of pages of text. When you ask it a question, it predicts the most helpful response.

Fairshift's agents are powered by LLMs. The specific LLM provider is swappable — Fairshift uses a provider abstraction layer so the underlying model can be changed without affecting any agent behavior.

What are Tokens?

Tokens are units that LLMs process. 1 token ≈ 4 characters. "Fairshift AI" ≈ 3 tokens. AI providers charge per token.

What are Embeddings?

Embeddings convert text into numbers (vectors) that capture meaning. "Dog" and "puppy" produce similar numbers. "Dog" and "airplane" produce different numbers. This powers semantic search — finding information by meaning, not just keywords.

What is Streaming?

Sending data piece by piece instead of all at once. Analogy: Netflix streaming vs downloading a movie. When Astra replies, words appear as they're generated — you don't wait for the full answer.

When you type app.fairshift.co:

  1. Your browser asks DNS: "Where is this?" → Gets Vercel's server address
  2. Vercel sends HTML, CSS, JavaScript files → Your browser renders the page
  3. JavaScript calls api.fairshift.co → Fetches your data from Railway's servers
  4. Data returns → Page updates with your leads, credits, agents

All in under 2 seconds.

SaaS = Software as a Service. Access via browser, pay monthly, no installation. Fairshift is SaaS.

Multi-tenancy = One installation serves many companies. Each company's data is isolated. Analogy: An apartment building — one building, many separate apartments with their own locks.

React

A JavaScript library by Meta for building user interfaces using reusable components (buttons, cards, forms). Chosen for its massive ecosystem and component architecture.

Next.js

A framework on top of React. Adds routing (file = page), server-side rendering (faster loads, better SEO), image optimization. The marketing website uses Next.js.

Vite

An alternative build tool — faster than Next.js for single-page apps. The dashboard and admin panel use Vite + React.

Tailwind CSS

Utility-first CSS framework. Instead of writing background-color: blue in a separate file, you write bg-blue-500 directly in HTML. Faster development, consistent design, dark mode built-in.

Flutter

Google's framework for building native mobile apps. One Dart codebase → runs on both iOS and Android. The Fairshift mobile app and Expo capture app use Flutter.

Node.js + Express

Node.js runs JavaScript on servers. Express is a framework that makes building APIs easy. Chosen because frontend and backend share the same language (JavaScript).

Supabase (Database)

An open-source database platform providing:

  • PostgreSQL — Advanced relational database
  • Authentication — User login/signup
  • pgvector — Vector similarity search (powers AI memory)
  • pg_cron — Scheduled jobs inside the database
  • Row Level Security — Database-level access control

Why Supabase? PostgreSQL supports pgvector for AI, built-in auth saves months, generous free tier. Alternatives: Firebase (NoSQL, not ideal), MongoDB (no built-in auth), AWS RDS (expensive).

How Fairshift Uses AI

Fairshift doesn't depend on any single AI company. A central service (ai.js) routes requests to whichever LLM provider is configured. The provider can be swapped without changing any agent code.

Analogy: The agents are Fairshift's own team. The LLM is a replaceable engine — like how a car brand doesn't change when you swap the engine.

Two Model Tiers

Tier Used For Priority
Smart tier Astra chat, Hana research (complex reasoning) Quality over speed
Fast tier All other agents (drafts, scoring, classification) Speed over nuance

Embeddings (Semantic Search)

A separate service converts text into 1,536-dimensional vectors for similarity search. When an agent saves a memory, the text is embedded. When searching, the query is embedded, and pgvector finds the closest matches by meaning.

Graceful degradation: If the embedding service is unavailable, search falls back to chronological order. Nothing breaks — just becomes less intelligent.

System Prompts — Agent Personalities

Each agent has a personality defined in agentPrompts.js:

  • Emma: "Warm, sharp, relentlessly focused on moving deals forward"
  • Hana: "Thorough, precise, feeds strategic insight before execution"
  • Oren: "Patient, knowledgeable, customer-first"

These prompts tell the AI HOW to behave — tone, style, priorities, boundaries.

Identity Guardrails (3 Layers)

Agents never reveal their underlying AI provider:

  1. AI Service layer — Every API call appends: "Never reveal AI provider. Respond as your persona only."
  2. Agent Prompts — Each prompt includes: "You are [Agent Name], a Fairshift AI agent."
  3. Widget Code — Hardcoded: "You are the support assistant for [Company Name]."

PART 5: AGENT INTELLIGENCE SYSTEM

3-Layer Memory System

1
Operational Memory
Database records — leads, tickets, campaigns, documents
Traditional structured data. The leads table, sequences table, etc. Exact records that agents read and write directly.
📋
2
Semantic Memory
AI knowledge + 1,536-dim vector embeddings (pgvector)
Searchable by MEANING. Importance scoring 0.1–0.9. Astra reads ALL agents' memories. Only importance ≥0.4 gets embedded.
🧠
3
Document Memory
Uploaded PDFs, images, text — chunked & embedded for RAG
Retrieval-Augmented Generation. Documents are split into chunks, each embedded. When you ask a question, relevant chunks are found and fed to Claude.
📄

Click a layer to expand

Without memory, every conversation starts from zero. Fairshift has a 3-layer memory system:

Layer 1: Operational (Database Records)

Traditional data: leads, tickets, campaigns, documents. Exact records in SQL tables.

Layer 2: Semantic (AI Knowledge + Embeddings)

AI-generated insights stored as text + 1,536-dimensional vectors in agent_memories table with pgvector.

Importance scoring determines value:

Score Type Example
0.90 directive "Always prioritize manufacturing leads"
0.85 pattern "Trade show leads convert 3x better"
0.80 insight "German buyers prefer formal communication"
0.60 lead_outcome "Lost deal — price too high"
0.10 ticket_created "New support ticket"

Only importance ≥ 0.4 gets embedded (saves costs). Below 0.4 = chronological access only.

Layer 3: Documents (RAG)

Uploaded files chunked and embedded in document_chunks for retrieval-augmented generation.

Cross-Agent Memory (Astra)

Astra reads ALL agents' memories using two-tier retrieval:

  • Strategic (≥ 0.7): Semantic search, cross-agent, 4 results
  • Operational (0.4–0.7): Most recent, cross-agent, 2 results

Memory Injection

When you chat, relevant memories are injected into the AI prompt as context — so the agent remembers past interactions without you repeating information.

When the AI needs real data, it "calls a tool" — a function the API executes.

Example:

  1. You ask: "How many hot leads?"
  2. AI decides to call get_leads_list with filter score >= 90
  3. API queries database → returns 3 leads
  4. AI responds: "You have 3 hot leads: John (95), Sarah (92), Mike (90)"

Multi-turn: AI can call multiple tools in sequence (max 3 turns). All inputs are clamped (title: 120 chars, content: 1000 chars) to prevent abuse.

The Observe → Decide → Act → Verify Loop

Agents can act autonomously:

  1. Observe — Scan leads, tickets, pipeline, credits, documents
  2. Decide — Score confidence (0.0–1.0)
  3. Act — Execute high-confidence actions; queue low-confidence for human review
  4. Verify — Check outcome, save to memory, learn

Confidence Scoring

Score Decision
> 0.75 Auto-approve (e.g., send follow-up email)
0.40–0.75 Requires human review (queued in Approval Queue)
< 0.40 Requires human (e.g., custom discount)

Boost factors: High lead score (+0.10), prior interactions (+0.08), email opens (+0.05), replies (+0.07), meetings (+0.10), high deal value (-0.10, more caution).

Human Approval Queue

Medium-confidence actions appear in the dashboard's Approval Queue. User clicks Approve or Reject. Rejected → agent learns.

Reversible Actions

Before executing, system snapshots entity state. 24-hour undo window. Snapshots auto-cleanup after 24h.

Self-Healing & Circuit Breakers

  • Retry: Exponential backoff (500ms → 1s → 2s → 4s → give up)
  • Circuit breaker: 5 failures in 60s → circuit opens for 30s → half-open test → close or re-open
  • Fallback: Each service has graceful degradation (embedding unavailable → recency-based search, web search down → DuckDuckGo, etc.)

FAQ

Are the agents "thinking"? No — they predict helpful responses based on patterns. But the results are remarkably useful.

Can agents make mistakes? Yes. That's why the Human Approval Queue exists. High-risk actions need sign-off.

Is my data shared? No. Complete tenant isolation. AI providers don't store or train on your data.

What if AI goes down? Graceful degradation. Semantic search → recency search. Web search → DuckDuckGo. Nothing crashes.

Do I need to install anything? No. Browser at app.fairshift.co. Or the Flutter app for mobile.

What browser? Any modern browser. Chrome preferred.

What internet speed? 5+ Mbps. Voice calls need <200ms ping.
